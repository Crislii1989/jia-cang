## 问题 5（P0）：详情页标题消失、备注内容缺失

**现状**
- 备注：`lib/screen/item_detail_page.dart:333` 经 `row(...)` 渲染，行组件（`:697-711`）是 **`maxLines:1 + ellipsis`** —— 长备注被截成一行，这是「内容缺失」的直接根源。
- 标题：`:179-187` 的 `Text(item.name)` 无 maxLines/overflow，代码上不该消失。需要复现确认：可能是长标题溢出、被某个父级挤压，或特定数据（如超长名/特殊字符）触发。

**方案**
1. 备注行改为多行自适应：不设 maxLines（或上限 6 行 + 「展开」），对齐 S3 稿的信息卡语言。
2. 标题区加防护：`maxLines: 2 + ellipsis` 兜底 + 排查父级约束；请用户提供「标题消失」的具体物品与截图，先复现再修，不做无根据的猜测式改动。
3. 顺手把详情页信息组改成统一的「属性行」渲染器（为问题 6 铺路：空值行可配置隐藏）。

**决策点**：备注是「完整展开」还是「超过 N 行折叠 + 展开」？

## 问题 2（P1）：首页搜索

**现状**
- `home_page.dart:102-137`：46pt（`46 * k`）**假输入框**，点击只 `context.go('/inventory')` —— 不传搜索词、不聚焦物品库搜索框（物品库搜索框高 38，过滤逻辑只匹配 name/location）。
- 「大小不对」：首页胶囊 46*k，与物品库搜索框（38）及设计稿行高不一致。

**方案（三选一）**
- **A. 保留 + 打通（推荐，改动最小）**：点击后跳物品库并自动聚焦搜索框（加一个 `pendingSearchFocusProvider` 之类，仿 `pendingCategoryProvider`）；高度对齐设计稿修正尺寸。
- **B. 缩小为普通入口**：首页搜索降为常规行高（如 44），纯入口样式，与整体密度一致。
- **C. 删除首页搜索**：物品库已有搜索，首页去掉后更简洁（设计稿 S1 是否含搜索条需回看稿子定）。

**决策点**：选 A / B / C？若 A，是否支持「首页输入词带过去」还是只聚焦？

## 问题 1（P1）：物品排序 + 筛选 + 物品标签系统

**现状**
- 排序枚举只有 newest/oldest 两种（`lib/models/enums/sort_type.dart`），仅按 `createdAt` 升降（`inventory_page.dart:162-169`）；排序状态存页面 State，**不持久化**，切分类页回来还会被 `_resetSecondaryState()` 重置。
- 首页四张统计高卡（在库/闲置/临期/出借）点击**全部只 `goInventory`，无状态过滤**（`stat_minis_section.dart:39-63`）——这就是「影响首页状态点击效果」：点「闲置 3 件」进去看到的还是全量列表。
- 筛选面板 `filter_panel.dart` 只有「收纳位置」一个条件。
- items 表**无 tag 列**；`ItemTagType` 只是展示用枚举，不是用户标签体系。

**方案（拆 4 步，可独立验收）**
1. **排序扩充 + 持久化**：排序枚举扩为 登记时间(新→旧/旧→新)、名称、分类、到期时间；选中值写 `shared_preferences`，下次进入保持。
2. **首页状态卡点击过滤**：新增 `pendingStatusProvider`（仿 `pendingCategoryProvider` 模式），四张卡点击 → 物品库自动按对应状态过滤并高亮，可一键清除。
3. **筛选面板扩展**：加「状态」（在库/出借/遗失/已用）与「分类」两个条件，与位置条件叠加。
4. **物品标签系统（建议单独版本，schema v9）**：items 加 `tags`（JSON 字符串列，沿用只加不减约定）；筛选面板加标签维度；物品库/详情页展示标签 chip。工作量明显大于前三步，不建议混在一轮。

**决策点**：① 排序默认项保持「新增时间」？② 首页状态卡点击后是「过滤 + 顶部可撤回的过滤条」还是「复用筛选面板」？③ 标签系统本轮做还是排到 v9？

## 问题 3（P1）：分类移动 / 主要品类露出

**现状**
- 分类页**已支持拖动排序**（`category_page.dart:573` ReorderableListView.builder + 「排序/完成」切换），但用的是已废弃的 `onReorder`（技术债，`newIndex` 语义与 `onReorderItem` 不同）。
- 首页 4 个分类圆 = `availableCategoriesProvider` 取 `sortOrder` 前 4，**与使用频次无关**——所以「主要使用的品类」出不来，只能靠手动排序间接影响。
- 分类页无常驻「物品数」展示（只在删除确认里统计）。

**方案**
1. 修技术债：`onReorder` → `onReorderItem`（核对 newIndex 语义），拖动排序保留。
2. 首页 4 圆选取规则（三选一）：
   - **A. 按物品数 Top4（推荐）**：常用品类自动浮上来，零配置。
   - B. 用户置顶：分类加 `pinned` 标记，分类页长按置顶（多一步配置，可控性强）。
   - C. 维持 sortOrder 前 4（引导用户去分类页拖动排序，现状已可用，只修文档/提示）。
3. 分类页每行常驻显示「N 件」物品数（数据现成，改动小）。

**决策点**：首页 4 圆选 A / B / C？

## 问题 4（P1）：闲置物品逻辑

**现状**
- `item_providers.dart:290-302`：`idle = status=='safe' && createdAt < 90 天前` —— 基于**登记时间**，不是「最近一次接触时间」：一件昨天刚整理过但半年前登记的物品会被误判闲置。
- 展示：首页统计卡 + 首页提醒列表；**无任何「处理闲置」的操作入口**，点击只进详情。

**方案（分两阶段）**
1. **阶段一：口径 + 入口**
   - 判定口径改为「最近接触时间」：优先用 `updatedAt`（没有则加列，沿用只加不减），编辑/出借/查看时刷新；阈值 90 天保持可讨论。
   - 首页闲置卡点击 → 物品库按「闲置」过滤视图（复用问题 1 的 `pendingStatus`/过滤机制），列表里能一眼看到闲置集合。
2. **阶段二：处理闭环**
   - 闲置物品提供批量/单个「处理」操作：标记为 已用(used)/遗失(lost)，或自定义「已处理」；处理后从闲置集合消失并可在统计里体现。

**决策点**：① 闲置口径认可「90 天未接触」吗（基于编辑/出借等事件刷新）？② 阶段二要不要做，还是先只有清单入口？

## 问题 6（P2）：物品属性多样化 + 空属性隐藏

**现状**
- items 表字段：name/location/status/categoryKey/roomId/cabinetId/slotId/photos/expiryDate/note/createdAt —— **没有价格、数量、购买日期、购买链接**（brand 已逻辑删除）。
- 详情页信息组只有 3 行（存放位置/登记时间/备注），不存在「空属性占位」问题——因为可展示属性本就太少。真正的诉求是**属性太单调**。

**方案（两步）**
1. **UI 先行（不动 schema）**：详情页改「属性行」渲染器——属性行按配置渲染，**值为空自动隐藏**；现有字段先套用。
2. **字段扩展（schema v9，与标签系统同轮做）**：加 可空列：价格 `price`、数量 `quantity`、购买日期 `purchasedAt`（是否要购买链接/保质期长短等由你定）；添加页/编辑页对应加可选字段行；空字段不显示。

**决策点**：需要新增哪些属性字段？（建议最小集：价格、数量、购买日期）

## 问题 7（P2）：电商订单导入

**现状**

- 路由 `/order-import` 已注册，但**我的页功能菜单没有入口**——UI 上完全不可触达的死功能。

**方案（先拍板去留再动手）**
- **A. 砍掉（推荐）**：删路由 + `order_import/` 页面组 + import_providers，减维护面；将来真要做再从 git 历史找回。
